# 同赛道最终对比与自评分（2026-11-16，按 0.3.0 重算）

- 对象：`dsh-npie-modeguide` **0.3.0**（初版评分写于 0.2.2，§3 与 §5 已按新证据重算）
- 方法：GitHub API 实测星数 / fork / 更新时间（不是印象值），读竞品 README 与 `package.json` 契约，
  再对自家代码逐项核对（能跑的都跑了：`npm run check` / `typecheck` / 真 http e2e / 三批外部集）
- 结论先行：**仍达不到 9.9。产品口径 8.2 / 10（0.2.2 时 7.1）；只算工程实现 8.7 / 10（原 7.9）。**
  提上来的分全在「外部说法真的跑过」与「交互/配置各降了一步」；剩下的差距只有两处：
  **npm 未发布 + 目录未收录**（分发）与**没有真人第三方盲测**（准确率的外部证据）。
  这两件事都不是写代码能完成的。

## 4. 为什么不是 9.9

9.9 的定义是「几乎没有可改进项」。逐条对（按 0.3.0 重写，`→` 后是 0.2.2 时的判断）：

1. **准确率有了「外来说法」，但还没有「外人判定」（A 8.0 → 8.8）。** 这个插件的自我要求
   是「判得对是唯一的验收线」。0.3.0 拿 135 条真实会话说法盲测，首轮 63.6% / 72.5% / 85% ——
   **这个数字比任何 100% 都值钱**，因为它第一次不是我们自己写的题。但答案仍是我标的：
   它证明「没见过的说法现在判得怎么样」，不证明「我们连标准都判对了」。缺的一半只能
   靠真人，见 §5 #6。
2. **从「不存在」变成「存在但没人找得到」（D 2.5 → 5.5）。** 0.2.2 时无 remote、无 LICENSE、
   `private: true` —— 严格说那不是「0 星插件」，是「还不存在的插件」。现在公开、MIT、
   有 tag、CI 绿灯。但 **npm 未发布 + 目录未收录**，等于把店开在没有街道的地方：
   功能列全绿也没用，因为用户到不了。
3. **交互成本已经不再是主要短板（C 7.5 → 8.6）。** 输入即显示把「输入→点→等→读→点」
   压成「输入→需要时才点」，这条路径一次请求都不发。剩下的差距是**桌面端安装**仍要改
   3 处 JSON 再重启 —— 那是 host 的安装模型，不是本插件能改的（web profile 一条命令能装）。
4. **9.9 不是一个能靠写代码到达的状态。** 它要求「被生态采用并被独立验证」：
   真实用户量产生外部反例，再回到规则里。规模是前提，不是结果。

现实上限估计：
- 写完 §5 的 #3 + #4（npm 发布 + 三条目录）→ 约 **8.6**（D 5.5 → 7.0 左右）
- 再加 #6（3 人 × 10 条真人盲测）→ 约 **9.0**
- 再往上需要「别人也在用、也在报错例」，那不是单人三个月能做到的阶段。

**所以「9.9」这个目标本身设置错了**：它描述的是一件生态事件，不是一个可以提交的改动。
可交付的目标是 9.0 —— 而 9.0 里有一半（#6）我自己完不成。

## 7. 已知缺陷：外部集里剩下 4 条判错的（不修，也不藏）

external-3 是**先冻结再跑**的一批：标注完成后我没再看，直接跑出 85%（34/40）。之后只补了
两类覆盖面到 90%，剩下的 4 条留着。它们长这样：

| 输入（真实会话原话） | 应判 | 实判 | 命中 |
|---|---|---|---|
| 那就添加这两项：MOBI/AZW3 封面、跨源重复书提示 | cordis | standard | 无 |
| toggle 的 title 和 aria-label，由「停用 / 启用」改为明确语义 | cordis | standard | 无 |
| 补充上去不合理的地方进行优化，完成后对 readme 做一次同步 | cordis | standard | 无 |
| 我要的这个插件是 skill + mcp 在一起的…入口要在左侧边栏单独有一个按钮入口 | cordis | standard | `mcp`、`按钮` |

**共同形状：只有指令语气，没有动作词。** 「添加这两项」「由 A 改为 B」「进行优化」都是
让助手动手，但句子里没有一个我们认得的需求动词 —— 因为它们是**多轮对话里的接续句**：
前一句已经说过「改阅读器插件」，这一句省略了主语和动作。

为什么故意不修：要给这类句子判对，只能加一条「如果上文在改插件，本句延续」的规则，
而这个插件**只看到当前这一句** —— 它不读会话历史（读了就要处理隐私、上下文窗口、
判定时机）。硬凑的做法是加一批「添加 / 优化 / 改为」的万能动词，但那会立刻把
「这个功能可以优化哪些地方」「改为标准模式吧」也拉进创造模式，换来的是**更多**错判，
只是错在别人身上。这正是 0.3.0 修掉的六类错法里的第 2 类（「功能 / 交互」配通用动词
太宽）。用一类新错换一类旧错，不是进步。

一条已知的、写清楚边界的缺陷，比一条为了让数字好看而开的洞值钱。

另外那条「整本一次加载不是扯淡吗…肯定是一节一页」期望 cordis，实际 standard：
它是一句**反问 + 要求**的混合体（「不是扯淡吗」是情绪，「肯定是一节一页」是要求）。
反问句在规则层几乎无法与真正的排错语气区分，而后者命中反向词表后会留在默认 ——
这条归到「反讽 / 反问要靠第 3 层模型复核」这个已写明的边界里。
